# MerchPress Bug Audit

Date: 2026-11-07

## Fixed and verified in this session

| ID | Area | Severity | Issue | Root cause | File(s) | Status | Verification |
|----|------|----------|-------|------------|---------|--------|--------------|
| BUG-001 | Backend / Cart & checkout | High | Stock was not reliably validated/decremented at checkout; concurrent checkouts could oversell. | `checkout_cart` did a Python read-modify-write on stock without an atomic decrement. | `backend/commerce/services.py`, `backend/commerce/tests.py` | FIXED AND VERIFIED | `select_for_update()` + `F("stock_quantity") - quantity` atomic decrement inside `@transaction.atomic`; tests for available/insufficient/zero stock, multiple quantities, rollback, stock never negative (71 backend tests OK). |
| BUG-002 | Backend / Cart | High | Adding the same product configuration could create duplicate cart rows. | `add_cart_item` did not aggregate by product+variant+design+method. | `backend/commerce/services.py`, `backend/commerce/tests.py` | FIXED AND VERIFIED | `add_cart_item` merges matching existing line and returns `created=False` (HTTP 200); different designs/variants stay separate. |
| BUG-003 | Backend / Catalog | Medium | Creating an existing `ProductPrintingMethod` link raised an unhandled `IntegrityError` (HTTP 500). | Duplicate creation was not pre-checked. | `backend/catalog/views.py`, `backend/catalog/tests.py` | FIXED AND VERIFIED | Pre-check returns HTTP 400 `"already linked"`; tests for first association, duplicate, invalid product/method. |
| BUG-004 | Backend / Commerce | Medium | Dashboard revenue returned unquantized floating-point decimals (e.g. `56.4300000000000`). | `money()` was not applied consistently to the aggregated revenue. | `backend/commerce/views.py`, `backend/commerce/tests.py` | FIXED AND VERIFIED | `money()` quantizes to `Decimal("0.01")`; tests for whole/decimal/rounding/zero/empty aggregation (`"56.43"`, `"0.00"`). |
| BUG-005 | Backend / Production | Medium | SVG export emitted Fabric `path` objects as XML comments instead of real `<path>` elements. | `_svg_object` returned a comment for `obj_type == "path"`. | `backend/production/render.py`, `backend/production/tests.py` | FIXED AND VERIFIED | `_serialize_path` converts Fabric path command arrays to SVG `d`; tests confirm `<path d="...">` elements, fill/stroke/opacity/transform preserved. |
| BUG-006 | Backend / Shopify | Medium | Webhook signing secret defaulted to the API secret; no product/inventory sync. | `SHOPIFY_WEBHOOK_SECRET = os.getenv(..., SHOPIFY_API_SECRET)`. | `backend/config/settings.py`, `backend/commerce/shopify.py`, `backend/commerce/views.py`, `backend/commerce/tests.py` | FIXED AND VERIFIED | Independent `SHOPIFY_WEBHOOK_SECRET` (defaults to `""`); HMAC verification, idempotent dedup, `sync_inventory`, order cancelled handling; valid/invalid/duplicate signature tests. |
| BUG-007 | Backend / Commerce | High | Checkout auto-marked orders paid (demo) with no real payment path; no Stripe integration. | Checkout was demo-only. | `backend/commerce/services.py`, `backend/commerce/views.py`, `backend/commerce/serializers.py`, `backend/commerce/urls.py`, `backend/commerce/models.py` (+migration), `backend/config/settings.py` | FIXED AND VERIFIED | Stripe Checkout sessions created server-side; amounts calculated backend-only; order left UNPAID until verified `checkout.session.completed` webhook; idempotent webhook; demo mode preserved; mocked-Stripe tests. |
| BUG-008 | Frontend + Backend / Auth | High | JWT access/refresh tokens stored in `localStorage` (XSS surface). | `lib/api.ts` used `localStorage` for tokens. | `frontend/lib/api.ts`, `frontend/lib/auth.tsx`, `frontend/app/editor/[slug]/page.tsx`, `frontend/app/admin/products/[id]/page.tsx`, `backend/accounts/authentication.py`, `backend/accounts/views.py`, `backend/accounts/urls.py`, `backend/config/settings.py`, `backend/accounts/middleware.py` | FIXED AND VERIFIED | Tokens stored only in HttpOnly cookies (`printora_access`, `printora_refresh`); frontend sends `credentials: "include"` and no longer touches `localStorage`; login/register/logout set/clear cookies; CSRF token endpoint + enforcement middleware; backend/auth/frontend tests + 8 Playwright E2E tests pass. |
| BUG-009 | Frontend / Checkout | Medium | Checkout was demo-only with no Stripe option despite backend Stripe integration. | Frontend checkout page always submitted `demo: true` and never called `/api/checkout/session/`. | `frontend/app/checkout/page.tsx`, `backend/commerce/serializers.py`, `frontend/lib/types.ts` | FIXED AND VERIFIED | Checkout fetches `/store/config/` for `stripe_configured`; shows Stripe card button when configured, demo button otherwise; Stripe session created server-side, order left UNPAID until verified webhook. |
| BUG-010 | Frontend / Design editor | Medium | Editor only offered PNG export, missing SVG and PDF options. | `handleDownload` hardcoded `file_type: "png"`; single download button. | `frontend/components/design-editor.tsx` | FIXED AND VERIFIED | `handleDownload(fileType)` supports png/svg/pdf; three export buttons added; SVG renders real `<path>` elements (BUG-005); PDF via Pillow renderer. |
